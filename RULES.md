# CounselConnect - Project Rules

All contributors must read and follow these rules. They are mandatory throughout development.

These rules govern architecture, UI design, functionality, validation, authentication, security, data integrity, audit, accessibility, and responsive design for the CounselConnect Judicial Case Management Platform.

## Rule Documents

| # | Document | Scope |
|---|----------|-------|
| 1 | [Architecture Rules](docs/rules/01-architecture.md) | CSR lifecycle, platform actors, AI boundaries |
| 2 | [UI Design Rules](docs/rules/02-ui-design.md) | Visual direction, color palette, prohibitions |
| 3 | [Functionality Rules](docs/rules/03-functionality.md) | Button behavior, state management |
| 4 | [Form Validation Rules](docs/rules/04-form-validation.md) | Frontend and backend validation |
| 5 | [Authentication Rules](docs/rules/05-authentication.md) | Registration, login, identity types |
| 6 | [Role Security Rules](docs/rules/06-role-security.md) | Authorization, endpoint protection |
| 7 | [Data Integrity Rules](docs/rules/07-data-integrity.md) | Transactions, constraints, storage |
| 8 | [Audit Rules](docs/rules/08-audit.md) | Audit events, append-only records |
| 9 | [Security Rules](docs/rules/09-security.md) | Passwords, uploads, secrets, CSRF |
| 10 | [Accessibility Rules](docs/rules/10-accessibility.md) | Labels, keyboard, focus, color |
| 11 | [Responsive Design Rules](docs/rules/11-responsive-design.md) | Desktop-first, tablet, mobile |

## Enforcement

- Every pull request must comply with these rules.
- Rule violations must be resolved before merging.
- Do not modify these rules without explicit approval.
